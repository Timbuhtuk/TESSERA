# Ленты, происхождение результатов и макросы

Результаты редактора расположены деревом: продолжение идёт вправо, повторная обработка того же результата создаёт ответвление ниже. Перетаскивание в промежуток между ветками и пункт «Вынести в отдельную ветку» меняют только расположение. Крестик удаляет одну карточку; её дети остаются видимыми ветками. Перетаскивание результата в исходники по-прежнему создаёт самостоятельный исходник с новой историей.

Общий разделитель под лентами изменяет их высоту; двойной щелчок переключает компактную и последнюю развёрнутую высоту. Разделитель между лентами изменяет их ширину. Прокрутка работает по обеим осям, Shift + колесо — по горизонтали. Предпросмотру остаётся минимум 240 DIP. Карточки сохраняют прежние размеры.

В компактной правой ленте показана текущая логическая папка проекта. В развёрнутой — заголовки папок и горизонтальные ряды изображений; заголовки сворачивают вложенность. Путь над лентой позволяет перейти к родителям. Переход по папкам не переключает открытое изображение. Общий ассет использует привязку именно к открытому проекту. Вне проекта сохраняются контексты общей библиотеки и непривязанных материалов.

## Макросы

ПКМ на результате → «Создать макрос…». Диалог принимает только непустое уникальное имя. После сохранения открывается «Инструменты → Обработка → Макросы»: общий список библиотеки, просмотр шагов и применение. Переименование и удаление находятся в контекстном меню списка. Esc и кнопка «Отменить» отменяют выполнение.

Применение использует выбранную основу редактора: исходник или результат. Промежуточные изображения остаются в памяти; после всех шагов сохраняется одна карточка с именем макроса и правильным родителем. При ошибке или отмене частичная карточка не создаётся; сообщение содержит номер и название шага. Отмена проверяется между шагами; удаление фона дополнительно проверяет её внутри процессора.

Поддержаны профильная обработка, размер, палитры/квантование, Cleanup Colors, выравнивание/сжатие сетки, монохром, ASCII-изображение, замена цвета, каналы RGBA, обрезка прозрачных краёв, автоматическое удаление фона и карта контуров. Карту контуров можно включить в макрос через «Создать макрос…» на её результате; параметры анализа сохраняются вместе с шагом. Операция `contours.clean` также выполняется из сохранённого JSON-макроса. Ручной ластик и исправления тайлов не воспроизводятся. Цепочка с неподдержанным шагом отклоняется целиком с объяснением. Макрос из результата макроса содержит раскрытую последовательность; первоначальное определение больше не требуется.

Размеры повторяются буквально в пикселях. Автоопределение ячейки и цвета фона выполняется на новом входе. Сжатие после автоматического выравнивания получает обнаруженную ячейку из того же запуска.

## Хранение и общий исполнитель

- `<library>/editor-history.json`: версия 1, высота/ширина лент, прокрутка, свёрнутые папки и отдельный порядок визуальных корней для каждого исходника.
- `generation.json`: `ParentGenerationId` сохраняет происхождение; `OperationId` — стабильный вид операции; `AppliedRecipe` — операции этого результата; `RecipeSnapshot` — полная последовательность от текущего исходника. `RecipeUnavailableReason` объясняет невозможность полного воспроизведения.
- `<library>/macros/<id N>.json`: независимое определение с `version`, `id`, `name`, упорядоченным `steps`. Схема и примеры: [формат макросов](../plugins/tessera/skills/tessera/references/macros.md).
- `PixelArtWorkflows`: модели, `MacroStore`, `WorkflowExecutor`, общий для WPF и CLI. Исполнитель вызывает обычные `PixelArtDownscale`/`PixelArtAlignment` процессоры. Рецепты не содержат файловых путей, темы и числа потоков.

Снимок рецепта не зависит от удаления родительских карточек или определения макроса. Перед удалением старого родителя библиотека фиксирует однозначно восстанавливаемые рецепты его детей. Старые PNG не пересчитываются. Миграция проверяет наличие нужных полей в исходном JSON; отсутствующие параметры не подменяются текущими значениями по умолчанию. Журналы и локализованные подписи не исполняются. Только известные старые названия операций используются для ограниченного распознавания старого формата.

Отсутствующие родители и циклы показываются с предупреждениями; исправление раскладки не переписывает происхождение. Дерево строится итеративно. `VirtualizingTray`/`TrayPanel` создают контейнеры только для пересекающих область просмотра карточек и отсекают невидимые соединительные линии.

## CLI и проверки

```powershell
tessera macro list --library C:\TesseraLibrary --json
tessera macro apply input.png --macro C:\TesseraLibrary\macros\ID.json -o output.png --json
dotnet run --project PixelArtAlignment.Tests -c Release -- --history-macros
dotnet run --project Pixelizator.Cli.Tests -c Release
```

`--history-macros` проверяет дерево из 30 000 результатов, перенос/удаление/циклы, точные размеры и прозрачность, независимость рецептов, неполную старую историю, связь с выбранной основой, одну итоговую карточку, папки/пустые папки/общие ассеты, обе темы, минимальный размер, сохранение после перезапуска и виртуализацию каталога из 20 000 исходников. Это проверки моделей и WPF с программными событиями и рендером; они не заменяют проверку настоящего ввода мышью.

Перед выпуском отдельно требуется проверить настоящую прокрутку, оба разделителя, двойной щелчок, drag-and-drop между ветками и в исходники, ПКМ/клавиатуру, создание/переименование/удаление макроса, отмену, минимальное окно и обе темы. Статус первичной приёмки: [отчёт QA](QA_HISTORY_MACROS_2026-10-24.md).
