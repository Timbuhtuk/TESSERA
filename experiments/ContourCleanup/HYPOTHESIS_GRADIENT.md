# Гипотеза 1: градиент как признак дефекта формы

Проверка выполнена на пяти FIMOZ после одинакового базового конвейера `finish-pixel-art` (157×157). Скрипт `RunGradientHypothesis.ps1` применяет существующий `clean-dark-contours` с настройками по умолчанию и с обязательной противоположностью общему градиенту (`--require-common-gradient`). Входной PNG для каждой версии один и тот же; результаты предыдущего прохода не подаются в следующий.

Размер всех выходов — 157×157, альфа не изменилась. PNG и полный JSON счётчиков лежат в локальном игнорируемом Git каталоге `artifacts/shape-gradient/`.

Это проверка только двух заранее выбранных режимов **комплексного очистителя** `clean-dark-contours`, а не самостоятельной модели нормалей/градиентов. Малое число изменений не доказывает, что каждый пиксель исправлен верно. Обязательный общий градиент почти полностью выключил очистку на этой выборке. Пока нет основания считать эти два режима достаточным механизмом решения всех названных пользователем проблем формы. Окончательный визуальный pass/fail отдаётся независимому валидатору.

## Итог независимой проверки

По фиксированному протоколу обычный режим получил **1/5 PASS**: на Assaultman, Bowman, Rifleman и StrongHand осветлены нужные тёмные штрихи оружия или разделителей. Строгий режим получил **5/5 PASS**, но четыре файла пиксельно совпали с базой, а на Rifleman изменены лишь две клетки. Сетка и альфа не меняются в обоих режимах, поэтому этот инструмент не исправляет силуэт и размер логического пикселя. Градиент пригоден как вспомогательный признак точечной правки, но сам по себе выигрыша формы на корпусе не показал. Полный отчёт — `VALIDATION_REPORT.md` в ветке `codex/contour-black-lines`, коммит `675aad7`.
