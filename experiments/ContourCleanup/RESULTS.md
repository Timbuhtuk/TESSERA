# Перчатка: промежуточная проверка

Запуск из корня ветки: `dotnet run --project experiments/ContourCleanup/ContourCleanup.csproj -c Release`.
Программа сохраняет исходник, результаты, карты замен, увеличенные области и атлас 57 замен в `experiments/ContourCleanup/artifacts/review/`.

Текущий общий режим `ContourNoiseCleaner` на окнах 3, 7 и 15 даёт соответственно 600/439/180 кандидатов и 23/84/7 замен. На перчатке его карта кандидатов слишком широко охватывает светлую текстуру, а замены не сосредоточены на чёрных линиях.

Экспериментальный проход ищет тёмный пиксель с малым числом тёмных соседей. Он требует, чтобы удаление пикселя не разорвало тёмную область, чтобы светлые соседи согласовывались по цвету, и сохраняет альфу. Параметры `dark-15-n3-g40-a3-c75`: LAB L < 15, максимум 3 тёмных соседа из 8, цветовой допуск LAB 28, увеличение L минимум 40, отступ 3 пикселя от прозрачности, согласие светлых соседей минимум 75 %. Заменено 57 пикселей. Число 8-связных тёмных компонент при LAB L < 15 осталось 23, число компонент размером до двух пикселей осталось 18. Размер 142×155 и все альфа-значения сохранены.

При просмотре на белом и чёрном фоне и в увеличенных областях большинство замен убирает выступы внутри чёрных линий. Манжета и заклёпки содержат самые неоднозначные места, поэтому вариант с L < 15 оставлен только как промежуточный.

Сравнение с градиентным фильтром: окна 3/7/15 отмечают соответственно 2/3/3 из этих 57 пикселей. Противоположность градиентов и тёмный выступ на линии почти не пересекаются на данном изображении. Повторные проходы с теми же параметрами меняют ещё 11 и 1 пиксель; для приёмки пока выбран только первый проход.

При LAB L < 5 тот же фильтр меняет 55 пикселей, при L < 10 — 58. Карта L < 5 почти совпадает с L < 15, но точнее ограничивает задачу чёрными пикселями. Дополнительная защита пикселей с противоположными тёмными соседями не изменила карту L < 5: спорные точки на манжете не лежат на прямой середине линии, а выглядят как выступы на её краю. Защиту исключили из прототипа как бесполезную на этом образце.

Итог для этой перчатки: выбран один проход L < 5 с остальными параметрами `dark-05-n3-g40-a3-c75`. При просмотре всех 55 фрагментов в атласе, результата при 1:1 и 6:1 на белом и чёрном фоне не найдено разрывов пальцев, ладони, большого пальца, заклёпок, манжеты или силуэта. Внешний край остался прежним благодаря отступу от прозрачности. Это локальная приёмка на данном образце, а не доказательство пригодности для других спрайтов.

Файлы для просмотра: `review/recommended.png` — PNG 142×155 с прозрачностью, `review/before-after-on-white-6x.png` — сравнение, `review/candidate-atlas.png` — все 55 замен.

## Проверка на 50 спрайтах, 26.10.2026

После локальной проверки на перчатке добавлен воспроизводимый набор из 50 спрайтов 72×72: 10 нарисованных мотивов × 5 вариантов цвета и расположения. Для каждого сохранён чистый PNG и версия с восемью намеренно добавленными тёмными пикселями. Координаты всех 400 вставок записаны в `corpus/manifest.json`. Это искусственный набор с известным эталоном, а не 50 независимых произведений разных художников.

Общий фильтр `ContourNoiseCleaner` с условием противоположности градиентов на перчатке пересекался с малой долей явных выступов. Поэтому экспериментальный фильтр тёмных контуров вынесен в `PixelArtDownscale/DarkContourNoiseCleaner.cs` и доступен как команда Tessera `clean-dark-contours`. Он проверяет восемь соседей, тёмную топологию, поддержку в 5×5, размер связной компоненты, сходство светлых соседей, продолжение противоположной пары цветов и повторяющиеся детали. В диагональных случаях он также сравнивает модуль и направление градиента пикселя с градиентами соседей похожего цвета. Пороги доступны через параметры CLI.

Запуск из корня этой ветки:

```powershell
dotnet run --project experiments/ContourCleanup/ContourCleanup.csproj -c Release -- generate-corpus
dotnet build Pixelizator.Cli/Pixelizator.Cli.csproj -c Release --no-restore -m:1
./experiments/ContourCleanup/RunCorpus.ps1
dotnet run --project experiments/ContourCleanup/ContourCleanup.csproj -c Release -- evaluate-corpus
```

`RunCorpus.ps1` вызывает собранный CLI Tessera по одному разу для каждого из 50 чистых и 50 загрязнённых PNG. Текущие настройки CLI по умолчанию: LAB L < 5, максимум 3 тёмных соседа из восьми и 2 по сторонам, цветовой допуск LAB 28, прирост светлоты от 20, согласие светлых соседей от 60 %, отступ от прозрачности 1 пиксель, один проход. Для короткого повтора 3×3 малой компоненты установлен предел 6 % от размера главного контура и максимум один тёмный сосед по стороне. Для диагонального случая: допуск цвета пары LAB 8, минимум 7 повторов со светлым центром, отношение модуля градиента к среднему у соседей не меньше 1,22; альтернативно противоположность направлений от 80 % при согласии соседей от 20 %. Остальные ограничения перечислены в `tessera clean-dark-contours --help` и в JSON отчёте.

Результат текущего прохода: изменены **399 из 400** вставленных тёмных пикселей, **398 восстановлены точно**. На 50 чистых контрольных изображениях **0 изменений**; на загрязнённых вне координат вставок **0 изменений**. Размер и альфа каждого результата совпадают с исходником. На `02-shield-04` (36,13) вместо эталонного светлого оттенка получился соседний тёмно-фиолетовый; на `10-gauntlet-04` (29,45) один тёмный пиксель остался без изменений. Суммарная квадратичная ошибка цветов в LAB уменьшилась с 2 279 162 до 5 218. Второй проход текущей конфигурации не дал новых исправлений.

Доработка после первого замера добавила сравнение повторяющихся окружений 7×7 и коротких окружений 3×3 на малых компонентах. Повторяющиеся глаза защищаются сравнением двух похожих компонент с допуском двух отличающихся соседних пикселей. Ещё два диагональных мостика удаляются при согласии светлых соседей от 90 %. Затем добавлены проверка прямого продолжения линии, отличие повторяющихся компонент и дополнительная проверка диагональной пары по повторению короткого окружения и градиенту. Направление градиента служит альтернативой отношению модулей: часть внесённых выступов направлена **в ту же сторону**, что и общий градиент похожих тёмных соседей. Эти проверки подняли число точных восстановлений с 365 до 398 без изменений чистых образцов.

Две неточные точки находятся на ступенчатом краю щита и на конце чёрной линии перчатки. У щита ближайшие светлые цвета относятся к двум оттенкам: выбор представительного цвета даёт более тёмный оттенок, тогда как эталонный пиксель светлее. У перчатки локальный угол похож на настоящий угол того же рисунка. Понижение обоих порогов поддержки 5×5 до 8 исправило последнюю тёмную точку, но повредило 70 чистых пикселей; отдельное правило для редких ступенчатых углов повредило 46. Грубое правило диагональной пары также отклонено: 70 повреждений чистых изображений. Текущая версия сохраняет детали, но **пока не удовлетворяет условию, что все 50 результатов выглядят чистыми**.

Для просмотра: `corpus/review-after/*.png` — чистый образец, загрязнённый, выход Tessera и карта изменений для всех 50; `corpus/review-after/missed-atlas.png` — крупное сравнение двух неточных точек; `corpus/evaluation.json` — метрики по каждому PNG; `corpus/features.csv` — признаки пропусков и побочных изменений. Прежняя перчатка с новыми настройками: `artifacts/glove-current.png` и `artifacts/glove-current-comparison.png`; изменён 91 пиксель, размер 142×155 и альфа сохранены. На текущей конфигурации отдельно проверен PNG с альфой 128: после восьми замен значения альфы всех пикселей совпали с исходником при повторном открытии. Это отдельные визуальные и технические ориентиры, а не подтверждение полной приёмки на наборе.
